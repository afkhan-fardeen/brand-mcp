Product Requirements Document (PRD): Multi-Brand Knowledge Base & AI Compositing MCP Server1. Product OverviewA multi-tenant Next.js knowledge base and API bridge connecting distinct brand asset libraries to AI assistants via the Model Context Protocol (MCP). The system supports 2-4 individual brands, ensuring the AI dynamically isolates and queries the correct brand's typography, campaign rules, and transparent product PNGs. It ensures generated lifestyle e-commerce images maintain 100% pixel-perfect product accuracy by routing requests to specialized compositing APIs.2. Target AudienceHuman Users: Marketing teams and brand managers overseeing multiple distinct brands from a central dashboard.AI Clients: Large Language Models (Claude Desktop, custom Gemini apps, Cursor) acting as creative agents capable of switching brand contexts on the fly.3. Problem StatementManaging multiple brands within a single AI context window causes "brand bleed" (e.g., the AI accidentally applying Seissense athleisure aesthetics to a Love Boo product).Standard text-to-image AI hallucinates or subtly alters actual e-commerce products when asked to place them in seasonal environments.Marketers need a way to generate strict, e-commerce-standard assets (like hero banners with negative space) for specific seasonal campaigns (e.g., Saudi National Day) using exact product SKUs.4. Proposed SolutionBuild a multi-brand Next.js application:Multi-Tenant Admin UI: A dashboard with "workspaces" for each brand to upload specific Brand Toolkits, Photography Guidelines, Layout Wireframes (e.g., hero banners), and transparent e-commerce product cutouts.Context-Aware MCP Server: An API where every tool requires a brand_name parameter. When the user says, "Make a Love Boo hero banner," the AI automatically scopes all database queries to that specific brand.Compositing Pipeline: The server routes the exact product PNG and an AI-synthesized prompt to a specialized compositing API to render backgrounds that adhere to the brand's layout and campaign rules, without altering the product.5. Core FeaturesA. The Next.js Admin Dashboard (Human Interface)Brand Workspaces: Separate environments for 2-4 brands to prevent asset mixing.Asset & Rule Uploading: Secure upload of product PNGs and text input for brand voice, Hex codes, lighting constraints, and e-commerce layout rules (e.g., 40% negative space for hero banners).Campaign Manager: Ability to input active campaign rules (e.g., "Saudi National Day: Use green Pantone 349 C and modern geometric patterns; avoid generic flags").B. The MCP Server (AI Interface)Tool: get_brand_guidelines: Requires brand_name. Retrieves specific visual rules and active campaign constraints for that brand.Tool: get_layout_rules: Retrieves spatial instructions for standard e-commerce assets (hero banner, square social, story).Tool: search_product_assets: Requires brand_name and product_query. Retrieves high-resolution transparent PNG URLs.Tool: generate_composited_shot: Accepts source image URLs, layout dimensions, and a highly detailed art-direction prompt from the AI, routing it to the external compositing API.C. The Compositing PipelineIntercepts the AI's image generation request.Locks the source product pixels (preventing AI hallucination).Generates the requested background, lighting, and shadows strictly following the retrieved brand, campaign, and layout rules.Returns the final image URL to the AI chat interface.6. User Flow (End-to-End Execution)Setup: Admin populates the "Seissense" workspace with product PNGs and adds campaign rules for Saudi National Day.Prompt: User opens Claude Desktop and asks, "I need a hero banner for Saudi National Day promoting these two Seissense products [Uploads Images]."Retrieval: Claude identifies the brand (Seissense) and asset type (hero banner). It calls:get_brand_guidelines(brand: "Seissense", campaign: "Saudi National Day")get_layout_rules(asset: "hero_banner")Synthesis: Claude writes a master prompt for the API: "1920x1080 resolution. Left 40% clean Saudi Green (Pantone 349 C) with subtle geometric texture. Right 60% features a white marble podium under soft studio lighting."Execution: Claude calls generate_composited_shot passing the attached images and the master prompt.Rendering: The Next.js backend sends the payload to the Compositing API, which anchors the products on the generated podium with accurate drop shadows.Delivery: The e-commerce-ready banner is returned inline to Claude.7. Technical ArchitectureFramework: Next.js (App Router)Database & Auth: Supabase (PostgreSQL, pgvector, Edge Functions, Supabase Storage). Schema includes a brands table, with all assets and rules relationally linked by brand_id.Protocol Integration: mcp-handler (Server-Sent Events for remote AI connections)Image API Integration: Photoroom API, Google Imagen API (Subject mode), or Replicate (Stable Diffusion ControlNet).
